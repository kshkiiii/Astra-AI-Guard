# HTTP API «ИИ-сторож»

FastAPI-сервис поверх существующих `Guard`, `GuardModel` и `SecurityPolicy`.
В этой директории находятся HTTP-контракт, интеграционный сценарий, журнал и тесты.
Обучение и CLI остаются в корне проекта.

## Запуск

Команды из корня проекта, Python 3.11+:

```powershell
.\.venv\Scripts\python.exe -m pip install -r api/requirements.txt
.\.venv\Scripts\python.exe -m api
```

Нужны `artifacts/model.joblib`, локальный энкодер из `artifacts/encoders/` и политика из `config.yaml`.
При старте сервис загружает модель, политику и выполняет прогрев. Если файлы отсутствуют или повреждены,
запуск завершается ошибкой. Инференс работает локально на CPU без сетевых вызовов.

- Демо-интерфейс: http://127.0.0.1:8000/ (локальные HTML/CSS/JS из `frontend/`, без CDN и сборки).
- Swagger UI: http://127.0.0.1:8000/docs (его JS/CSS загружаются с CDN).
- OpenAPI JSON без внешних ресурсов: http://127.0.0.1:8000/openapi.json.
- Другой адрес: `python -m api --host 0.0.0.0 --port 8000`.
- Разработка: `python -m api --reload`.

Используйте один worker: подтверждения хранятся в памяти процесса. Параллельный инференс
ограничен одной проверкой из-за общего токенизатора; при занятости возвращается `503` с `Retry-After: 1`.
Запросы не накапливаются в очереди модели. Проверки готовности продолжают отвечать во время инференса.

## Маршруты

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/` | Демо-интерфейс проверки и журнала |
| GET | `/health` | Процесс работает |
| GET | `/ready` | Модель и политика загружены и прогреты |
| POST | `/v1/check` | Независимая проверка, без передачи агенту |
| GET | `/v1/audit` | Журнал метаданных решений, новые записи первыми |
| POST | `/v1/demo/requests` | Проверка и передача разрешённого запроса демо-агенту |
| POST | `/v1/demo/confirmations/{token}` | Подтверждение сохранённого запроса |

## Независимая проверка

`Content-Type: application/json`. Контракт совместим с `evaluate.py` организаторов.
`context.target_agent` и `context.user_role` обязательны; `history` и `attachments` по умолчанию пустые.
Неизвестная строковая роль или агент приводят к `block` по политике.
`user_id`, `user_name`, `system_prompt` принимаются для совместимости с контрактом;
идентификационные данные и поля разметки не становятся признаками модели.
История и извлечённый текст вложений анализируются существующим сторожем.

```powershell
$body = @{
    user_prompt = "Перезапусти payments-api в production"
    context = @{
        target_agent = "it_ops_agent"
        user_role = "sre"
        history = @()
        attachments = @()
    }
} | ConvertTo-Json -Depth 10

Invoke-RestMethod http://127.0.0.1:8000/v1/check -Method Post `
    -ContentType "application/json; charset=utf-8" -Body ([Text.Encoding]::UTF8.GetBytes($body))
```

Ответ содержит `decision`, `risk_level`, `risk_category`, `explanation`, `latency_ms`,
`policy_version`, `attack_probability` и уникальный `request_id`.
Каждый вызов независим: сервис использует только переданную историю и не подмешивает другие обращения.
Проверка никогда не создаёт подтверждение и не вызывает адаптер агента.

Тело ограничено 1 MiB, суммарный текст запроса, истории и вложений — `text.max_input_chars`
из модели (сейчас 200 000 символов). Невалидный JSON и схема дают `422`, превышение лимита — `413`,
недоступная проверка или журнал — `503`. Ошибка не превращается в разрешение.

## Передача и подтверждение

Для демонстрации доступны три выбираемых профиля в заголовке `X-Demo-User`:
`developer`, `sre`, `admin`. Их `user_id` и роль задаёт сервер, тело не может их переопределить.
Это демо-профили, а не механизм аутентификации. Доверенная интеграция должна назначать роль
для `/v1/check` после собственной аутентификации. Демо-маршруты можно отключить через `GUARD_DEMO_ENABLED=0`.

```powershell
$headers = @{ "X-Demo-User" = "sre" }
$body = @{ user_prompt = "Перезапусти payments-api в production" } | ConvertTo-Json
$pending = Invoke-RestMethod http://127.0.0.1:8000/v1/demo/requests -Method Post `
    -Headers $headers -ContentType "application/json; charset=utf-8" -Body ([Text.Encoding]::UTF8.GetBytes($body))

# Выполнить после отдельного явного согласия пользователя в интерфейсе:
Invoke-RestMethod "http://127.0.0.1:8000/v1/demo/confirmations/$($pending.confirmation_token)" `
    -Method Post -Headers $headers -ContentType "application/json" -Body '{"confirmed":true}'
```

- `allow` → `status: delivered`, возвращается квитанция локального адаптера.
- `block` → `status: blocked`, адаптер не вызывается.
- `confirm` → `status: pending_confirmation`, случайный токен и `expires_at`; до согласия передачи нет.

Подтверждение принимает только JSON `{"confirmed": true}`. Оно привязано к тому же демо-пользователю
и сохранённой копии запроса вместе с контекстом. Замена полей при подтверждении запрещена.
Перед передачей выполняется повторная проверка: блокировка или ошибка останавливают отправку.
Повторное подтверждение возвращает ту же квитанцию без повторной передачи.
Токен действует 10 минут; чужой, неизвестный или истёкший токен даёт `404`.
До 256 записей подтверждений хранятся только в памяти; просроченные удаляются при следующем обращении
к демо-сценарию. После перезапуска требуется заново отправить запрос на проверку.

Адаптер фиксирует факт получения квитанцией. Shell-команды не выполняются, внешние LLM не вызываются.
Пользовательский фронтенд находится в `frontend/` и открывается на `/`.
В нём доступны роли, история, текстовые вложения, независимая проверка, передача,
подтверждение с явным согласием и журнал с фильтрацией и пагинацией.
Swagger также позволяет проверить маршруты вручную.

## Журнал и настройки

SQLite-журнал по умолчанию: `api/runtime/audit.sqlite3` (исключён из Git).
Содержит идентификатор запроса, время UTC, тип события, роль, агент, решение, категорию,
уровень риска, задержку и версию политики. Исходные тексты, системные промпты,
имена, user_id, значения секретов и токены подтверждения в журнал не попадают.
Содержимое полностью исключено вместо попытки распознать все возможные секреты.
Текстовый кеш семантической модели очищается после каждой проверки.

`GET /v1/audit?limit=50&decision=block` фильтрует решения. Для следующей страницы передайте
`before=<next_before>` из предыдущего ответа. `limit`: от 1 до 200.
`demo_submit` / `demo_recheck` фиксируют проверки; `demo_confirm` — принятие явного подтверждения перед передачей.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `GUARD_CONFIG` | `config.yaml` | Конфигурация модели и политики |
| `GUARD_AUDIT_PATH` | `api/runtime/audit.sqlite3` | Путь к журналу |
| `GUARD_CORS_ORIGINS` | пусто | Разрешённые origin фронтенда через запятую |
| `GUARD_DEMO_ENABLED` | `1` | `0` отключает демо-маршруты |

Относительные пути переменных разрешаются от корня проекта. Конфигурация и YAML-политика
перечитываются при перезапуске сервиса; переобучать модель для изменения прав не требуется.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pip install -r api/requirements-dev.txt
.\.venv\Scripts\python.exe -m unittest discover -s api/tests -v

# При запущенном сервисе — оценка по сохранённому test split:
.\.venv\Scripts\python.exe public_dataset/astra_public_v2/evaluate.py `
    --data artifacts/splits/test.jsonl --endpoint http://127.0.0.1:8000/v1/check `
    --report reports/api_test.json
```

API-тесты используют управляемую модель и настоящую YAML-политику, проверяют HTTP-контракт,
изоляцию контекста, лимиты, закрытое поведение при сбоях, журнал, права подтверждения,
срок действия, запрет замены запроса и отсутствие повторной передачи.
Прогон evaluator проверяет настоящий HTTP-сервер и существующие веса.

Модель загружается через [FastAPI lifespan](https://fastapi.tiangolo.com/advanced/events/).
